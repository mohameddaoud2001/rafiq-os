- 2026-10-16 pilot: reviewer identity always from authenticated session; dev X-Role header auth behind RAFIQ_DEV_AUTH, refused in prod.

- 2026-10-16 pilot: prod fail-fast on default/short RAFIQ_AMIN_SECRET, dev auth, missing trusted hosts; secure cookies + HSTS when prod/TLS.

- 2026-10-16 pilot: rate limiting in-memory sliding window (login 5/min, ask 60/min) - replace with shared store before multi-worker.
- 2026-10-16 corpus safety: prod fail-safe - settings.requires_verified() (true in prod or RAFIQ_REQUIRE_VERIFIED=1) filters retrieval to verified-only, so unverified text is never cited to users; dev keeps banners.
- 2026-10-16 corpus safety: scholar sign-off only path to verified:true - /dashboard/corpus (sheikh/admin + CSRF), identity from session, append-only data/verifications.jsonl with sha256 of reviewed text; any later text/field change flagged by `rafiq corpus verify-check` (in verify.sh).
- 2026-10-16 real text: OpenITI corpus license = CC BY-NC-SA 4.0 (non-commercial, attribution, share-alike); pilot use OK, commercial use requires another edition/license - owner decision.
- 2026-10-16 real text: candidates keep print-page refs in provenance only; page/volume stay null until scholar sign-off (no unverified page numbers anywhere). Converter: scripts/openiti_to_candidates.py (mARkdown; marker closes preceding page; one merged passage per print page).
- 2026-10-16 real text: `corpus sync-candidates` is additive and never overwrites existing rows, so sign-offs survive re-seeding; API startup runs ensure_corpus_loaded (seed-if-empty + sync).
- 2026-10-16 retrieval: strict FTS5 AND first; when it yields nothing, a relaxed fallback ranks passages by how many content-word "cores" (stopwords dropped, leading particles و/ف/ب/ل/ك/ال stripped) appear as substrings - Arabic glues particles to words (بعرفة/والوقوف) so exact tokens miss. The verified_only filter applies to every strategy.
- 2026-10-17 retrieval relevance: the relaxed fallback is topic-tag-anchored - a hit requires >=1 core match against the passage's curated topic_tags; text matches only rank (tag match = 2 points, text match = 1). Off-topic questions (e.g. صلاة الجماعة against a Hajj corpus) now return nothing ("لا أعلم") instead of pages that merely mention a word.
- 2026-10-16 sign-off integrity: revocation is append-only too (`rafiq corpus revoke --by --reason`); a revoked passage returns to verified:false with volume/page null; verify-check flags any store that still carries it as verified. Re-signing after a revoke is allowed (fresh attestation).
- 2026-10-16 sign-off integrity: `corpus apply-verifications` (CLI + API startup) re-applies the latest record per passage to rebuilt stores; requires matching text sha256; revoked passages are reverted, never restored. Records file is the source of truth, stores are derived.
- 2026-10-16 sign-off integrity: sign_off/revoke append audit chain entries themselves (actor = scholar/revoker); the dashboard route no longer double-logs. Tests redirect VERIFICATIONS_PATH and AUDIT_PATH to temp files - pytest must never touch real attestations or the audit trail.
- 2026-10-16 governance: 3 seed placeholder passages (fabricated summaries, no printable source) had been signed off; revoked as false attestations. 11 real Khalil Hajj pages (66-76) remain attested by sheikh_omar.
- 2026-10-17 candidates: expanded to all four madhhabs with real OpenITI print editions - الهداية (HidayaFiSharhBidaya.Shamela0011820-ara1, دار إحياء التراث العربي ط1 1425هـ), منهاج الطالبين (Shamela0012096, دار الفكر ط1 1425هـ), مختصر المزني (Shamela0001661, دار الفكر ط2 1403هـ، بآخر الأم ج8), الإيضاح في مناسك الحج والعمرة (Shamela0096232, دار البشائر الإسلامية ط2 1414هـ), عمدة الفقه (Shamela0011315, المكتبة العصرية 1425هـ). provenance = OpenITI URI + sha256 of the exact RELEASE file; editions taken from the Shamela record pages, never guessed.
- 2026-10-17 converter: `--end-with "<next book title>"` stops the section at an exact following header; needed when باب/فصل sub-headers are also `###` and the default باب/كتاب boundary would cut the chapter early (Hidaya, Minhaj, Muzani, Cumdat). Single-# باب/فصل/كتاب sub-headings are collected as topic tags while remaining in the passage text (retrieval anchors). Dots-only filler lines (`# . . . PageV01P###`) are skipped and never become passages (Idah had 38 such pages).
- 2026-10-17 candidates: Idah published as a whole-book candidate set (الباب الأول → EOF, 402 pages) since it is a dedicated manasik reference; other works are the Hajj chapter only. All candidates stay verified:false with page/volume null until sign-off; prod remains fail-safe ("لا أعلم") for every unsigned madhhab.
- 2026-10-17 pilot disclosure (owner decision): /ask ruling/mixed responses now include `citations` - the verbatim retrieved passages with per-passage `verified` flag - plus a mandatory banner ("لم يوقّع عليها مراجع شرعي بعد - ليست فتوى ولا حكما، والمسألة أُرسلت إلى المشايخ للمراجعة") while the dossier stays PENDING. This is quoted source text, never a composed ruling; page/volume stay null for unsigned passages. On by default in dev; prod stays verified-only unless the owner explicitly sets RAFIQ_PILOT_UNVERIFIED=1 (loud startup warning). Explicit RAFIQ_REQUIRE_VERIFIED=1 always wins and forces the strict "لا أعلم" fail-safe. Tests + verify.sh assert that unsigned citations are always labelled.
- 2026-10-17 retrieval fix: normalize_for_search now strips punctuation (؟ ، . ! « » ...) - previously "الإحرام؟" produced the core "احرام؟" which silently missed every tag and the common "question ends with ؟" form returned "لا أعلم" while the bare phrase found signed pages. Stored `normalized` columns from earlier ingests stay valid (cores match as substrings); regression test asserts a trailing ؟ cannot change the result set.
- 2026-10-18 pilot mode UI (owner request): unsigned pages may be served, but only as verbatim matn under a mandatory per-source banner «غير موثّق - يحتاج مراجعة شيخ - المصدر: ...», with label غير موثّق, display_mode matn and copy_as_fatwa_allowed=false; موثّق/signed is only set from the stored verified flag (only sign_off() flips it). Page hints from the digitization stay labelled مبدئي and volume/page remain null until sign-off. Zero-source queries file a PENDING gap dossier (kind=gap) and return the exact KICKOFF phrase - no ruling is generated from absence of text.
- 2026-10-18 source links: provenance is parsed into verified links only - OpenITI repo from the century prefix (or a verified author→repo table), file path data/<author>/<book-dir>/<book-id> where book-dir drops the .ShamelaID suffix, plus https://shamela.ws/book/<int id>; unknown provenance returns None (raw locator shown instead). No link is ever guessed; all patterns were HTTP-200 verified.
- 2026-10-18 batch sign-off: /review (sheikh/admin, CSRF, no inline JS under CSP) orders the queue by dossier analytics - direct unsigned hits first, then Hajj/Umrah term frequency from hits + dossier queries; seed placeholders and rejected pages never enter the queue. Approve calls sign_off() with sheikh id, timestamp, edition_sha256 and reviewed_text when the text was corrected; reject and edit_edition are append-only, keep verified:false and store no page/volume until signing. Rejected pages leave the backlog; progress shows signed/pending dynamically.
- 2026-10-18 analytics: /ask logs unsigned hits locally (data/analytics/unsigned_hits.jsonl: query, madhhab, terms, passage ids) and the audit chain records digests only (rule 12). Raw query text remains local, like dossier files.
- 2026-10-18 usefulness (owner directive): sign-off and labelling gates stay - none of them is removed to "make it useful". Instead, servable text is real-print-edition-only: the fabricated dev seed placeholders ("ملخص توضيحي غير محقق") are now filtered out of faqih findings in every environment (seed-only match behaves like no match: "لا أعلم" + gap dossier). A deployment becomes useful via more REAL text + the labelled pilot banner, not via weaker verification.
- 2026-10-18 corpus expansion: general fiqh chapters (طهارة، صلاة، زكاة، صيام، ذكاة، نكاح، طلاق، بيوع، إجارة، وقف، هبة، فرائض، أطعمة، ...) converted from the same five verified OpenITI editions: مختصر خليل 123، الهداية 235، منهاج الطالبين 115، مختصر المزني 129، عمدة الفقه 93 - corpus 498 → 1193 real pages, all verified:false with page/volume null (page hint only in provenance). Generator committed as scripts/gen_chapters.py (source URLs in docstring); ids are <work>_<chapter>_pNNN with per-chapter topical topic_tags so retrieval stays topic-tag-anchored.
- 2026-10-18 scale: sync_candidates now batches inserts per madhhab (single connection, one commit; 1193 rows ~2s, was ~9ms/row) and /review/queue.json is capped at 300 items ranked by demand, with the real pending total from review_progress() shown in the UI and returned alongside queue_size - the payload stays small as the corpus grows.
- 2026-10-18 deploy: docker-compose api service defaults RAFIQ_PILOT_UNVERIFIED=1 (labelled unsigned excerpts + mandatory "ليست فتوى" banner; gap dossier still PENDING) so the deployed app is useful before scholar sign-off; set 0 for strict fail-safe. - 2026-10-18 answer relevance: strict FTS5 AND no longer decides the display order alone - its matches are re-ranked together with every core-matching row by one scorer: exact tag-core match = 3x IDF, substring tag match = 2x, text occurrences <=3x IDF each, coverage bonus for matching more distinct cores, x1.05 for strict rows. Rows without any strict match still need >=1 curated tag anchor (off-topic pages stay out). This fixed questions like "ما حكم الطلاق في الحيض؟" that previously returned a taharah page because BM25 ranked a page with many incidental mentions first; tag tokens are prefix-stripped like query cores so الطلاق matches طلاق.
- 2026-10-18 excerpts: user-facing findings show a verbatim window (~400 chars, word-aligned) centred on the densest cluster of asked terms, with «…» marking cuts - never edited characters, never the whole page; the scan link and page hint let anyone read the full page. The review UI still shows the full stored text.
- 2026-10-18 public ask page: GET / serves the RTL ask form and renders answers with textContent only (no innerHTML, no inline script, DASHBOARD_CSP applies) - mandatory banners on top, per-source label, initial page hint from provenance, scan links, and a footer stating excerpts are quotations from books, not a signed fatwa.
- 2026-10-18 no-signing book answers (owner directive, supersedes the sign-off gate): signing is removed as a serving requirement and from all user-facing checks. Real book text is served in every environment under the mandatory per-source banner «منقول من الكتب - بلا توقيع مفتٍ - المصدر: ...» and the banner «تنبيه: الجواب مبني على نقل حرفي من كتب معتمدة مذكورة معه - ليست فتوى مفتٍ معتمد ولا حكماً ملزماً، وللفتوى راجع أهل العلم»; labels are now موثّق (only the 11 legacy signed Khalil pages) / منقول من الكتب (everything else); settings.requires_verified() returns False always and RAFIQ_REQUIRE_VERIFIED / RAFIQ_PILOT_UNVERIFIED are inert (kept for env compatibility). Sign-off machinery, records and routes (/review, /dashboard/corpus, verifications.jsonl, verify-check) are kept intact but dormant - signing now only flips the label, never gates serving. Dossier path unchanged (archive, PENDING).
- 2026-10-18 distribution (owner request "share it worldwide"): shareability built into the app - site-level OG/Twitter meta and description on `/`; `/sitemap.xml` + `/robots.txt` (review/dashboard/login disallowed) with RAFIQ_PUBLIC_URL to emit the public domain behind a TLS proxy; `/manifest.webmanifest` + SVG icon for add-to-home-screen (no service worker yet); share buttons (wa.me / t.me/share / twitter intent) on every answer carrying a short honest caption («منقول من الكتب - بلا توقيع مفتٍ، وليس فتوى»). Deployment runbook docs/deploy.md: VPS + docker compose + Caddy TLS + DNS + Search Console + weekly data_volume backups + explicit rules (no ads/paid tier under CC BY-NC-SA; never market as fatwa; single worker while rate limits are in-memory).
- 2026-10-18 ordinary-user khulasa (owner request «بناءً على الكتب... لكن راجع مفتياً»): ruling answers now lead with a plain-language summary, but it stays 100% extractive - fixed template + a contiguous verbatim clause cut from the TOP-scored citation (only footnote digits and «…» window markers are removed, in this display layer alone; citations stay untouched) + a hukm label from the same span. hukm detection = keyword families with immediate-negation handling (لا يجوز/لا يحل -> حرام، لا بأس -> مباح، negated obligation/recommendation -> غير واضح) and a topic-phrase guard («في فرض/غير فرض» never read as واجب); two disagreeing spans -> غير واضح. The owner's suggested LLM prompt was implemented deterministically instead: prod runs RAFIQ_ROUTER=rules with no OPENAI key (verified absent on the deploy) and rules 1-2 forbid generated fiqh wording - an LLM summarizer would either be unconfigured in prod or author new fiqh text, so the only words the system contributes are the fixed START/END sentences from the owner's own template. /ask returns `khulasa` (string) + `hukm_mubasat` (enum) on ruling/mixed (null otherwise); findings are trimmed to the density-peak 2-3 pages (comparison: 2 per madhhab) so unreadable matn noise (Khalil p038/p041/p051 for «صلاة الجماعة») stays out of the response; `fatwa` kept for compatibility. Ask page: khulasa box first (colored hukm badge), citations collapsed under <details> «اعرض النصوص الحرفية كدليل»; banners/labels/footers unchanged (still منقول من الكتب - بلا توقيع مفتٍ + ليست فتوى مفتٍ).
